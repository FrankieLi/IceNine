## 3. Decisions taken at decision points (plan default each time)

* After step 2 (the catalogue) the run continued into steps 3 and 4 without a stop.
* Walk design: the plan's "log-spaced radii" cannot resolve events at large radius (several events per step), so the
  full-sample walk is dense (0.0005 degree to 5 degrees) and E0 uses a dense 0 to 0.5 degree plus four fine windows;
  edges per degree are measured in the same step everywhere.
* Reflection lists: the screen's Q-max 5 list is a subset of the complete cost's list but with different indices;
  `peak_rejects.py` maps by the reciprocal vector. (A first version compared the same index in both lists and
  gave different peaks; found by looking at the vertex pixels, fixed before any number was used.)

## 4. What went wrong, and what was redone

* `peak_rejects.py` first compared reflection index across the two lists (see above).
* The first draft of the pixel-crossing diagram picked a thin triangle whose lit pixels were hard to see; it now picks
  the event with the largest triangle.
* A foreground `sleep` in a command was moved to the background by the tool; the polling loops were rewritten as
  short loops.
* The tables script first used the column name "rule" for both the overlap rule and an event type in the flips table
  (the rule label vanished); columns are now "cause: ...".

## 5. Could be done better

* The E0 0.5-to-5 degree regime is sampled in four 0.05-degree windows per ray, not continuously.
* Events of one type on one peak inside one step count once, so pixel events per degree are lower bounds at the finest
  scale.
* Rule-flip counts are by attribution priority; a frame and a pixel event in one step count as a frame event.
* The detector-edge cause of the three rejected peaks is shown from the traces (all and only the peaks whose centre is
  beyond the edge with the box reaching in); a counterfactual run of a screen that ignores the box was not done.
* The 13 pass differences at level 0 and the 4, 1 and 0 at levels 1 to 3 were not traced to a cause.
* Per-level parity covers six voxels, one C++ run each (the C++ random stream does not enter the screen).
